# Proteus Controller Compilation and OpenAPI Functional Testing Specification

## System Scope

- Compile generated controller route suppliers with the JDK 27 compiler API.
- Generate controller sources concurrently without persistent compilation caching.
- Preserve deterministic route and endpoint metadata order.
- Prevent partial route or endpoint registration when source generation or compilation fails.
- Expand running-server OpenAPI 3.1 functional coverage.

## Runtime Baseline

- Source and bytecode release: Java 27.
- Required runtime compiler: `ToolProvider.getSystemJavaCompiler()`.
- The framework fails startup when the runtime compiler is unavailable.
- SourceBuddy is not a runtime dependency.
- HTTP serving remains Undertow.

## Controller Compilation API

```java
public interface ControllerCompiler
{
    Map<String, Class<? extends Supplier<RoutingHandler>>> compile(
        Map<String, String> sources,
        ClassLoader parentClassLoader
    );
}
```

- Source map keys are fully qualified generated class names.
- Source map values are complete Java compilation units.
- The returned map uses the same keys as the source map.
- The returned classes are defined by one generated-class loader with `parentClassLoader` as its parent.
- `compile` throws `ControllerCompilationException` when compilation fails or a declared generated class cannot be loaded.

## JDK Compiler Implementation

- `JdkControllerCompiler` obtains the compiler from `ToolProvider.getSystemJavaCompiler()`.
- `JdkControllerCompiler` compiles all source units in one `JavaCompiler.CompilationTask`.
- Input source units are `SimpleJavaFileObject` instances backed by UTF-8 source strings.
- Output class units are `SimpleJavaFileObject` instances backed by byte arrays.
- A forwarding standard file manager stores every generated bytecode class by binary name.
- A generated-class loader defines stored bytecode only after a successful compilation task.
- Compiler diagnostics include diagnostic kind, generated class name, line, column, and message.
- Compilation failure does not define any generated class.
- Compiler options include the project Java release and the runtime class path.

## Generated Controller Batch

- `ProteusApplication.buildServer()` sorts registered controller classes by fully qualified name.
- Each controller source is generated in an independent virtual-thread task.
- Each task creates one `HandlerGenerator` and one private `NavigableSet<EndpointInfo>`.
- Each task returns a `GeneratedController` value containing:
  - Controller class name.
  - Generated route supplier class name.
  - Complete source string.
  - Immutable sorted endpoint metadata.
- Source generation waits for all tasks before compilation begins.
- Source generation failure cancels outstanding tasks and fails startup with the controller class name and cause.
- Generated sources are ordered by generated class name before the batch compiler runs.
- Successful batch compilation returns route supplier classes in the same deterministic order.
- Route suppliers are instantiated and merged into the application `RoutingHandler` in controller class-name order.
- Endpoint metadata is merged into the application endpoint registry only after every supplier class loads successfully.

## Endpoint Metadata Concurrency

- The application endpoint registry is a `ConcurrentSkipListSet<EndpointInfo>`.
- `EndpointInfo` comparison fields are immutable after insertion:
  - HTTP method.
  - Path template.
  - Controller name.
  - Controller method.
- Each `GeneratedController` owns private endpoint metadata until the entire generated batch has compiled and loaded.
- A failed generated batch leaves the application endpoint registry unchanged.
- Public endpoint metadata iteration remains sorted by `EndpointInfo.compareTo`.

## Lifecycle and Telemetry

- `ProteusApplication` owns an application-scoped `ControllerCompiler` binding.
- No compiled source or generated class survives application shutdown.
- `buildServer()` logs source-generation duration, compilation duration, route-merge duration, controller count, and generated source count.
- Timing values are informational and are not behavioral test assertions.

## OpenAPI Running-Server Coverage

- OpenAPI tests start a Proteus application and retrieve the served documents through JDK `HttpClient`.
- JSON, YAML, and YML document endpoints return HTTP `200` with their declared media types.
- Parsed JSON and YAML documents have equivalent OpenAPI version, info, paths, components, and security schemes.
- Every served operation has a non-empty operation id, summary or description, and at least one response.
- Every local `$ref` resolves against the served document.
- Every response content schema reference resolves against `components.schemas`.
- Typed generic, raw generic, explicit response, inferred response, metadata-only response, array response, and unannotated default response schemas have the declared shape.
- Request bodies cover JSON, multipart, requiredness, encoding metadata, and declared response schema.
- Query and header parameter metadata covers type, format, requiredness, bounds, enum values, examples, and descriptions.
- Header and link metadata covers scalar and array schemas, examples, operation ids, response-body expressions, and extension values.
- Security components contain the declared bearer and API-key schemes.
- Public, authenticated, role-protected, and denied operations have their declared OpenAPI security metadata.
- Documentation HTML and static OpenAPI UI routes return expected media types and document references.
- Every documented sample application endpoint is invoked through its served route and returns the documented response status and media type.

## Controller Compilation Verification

- Unit tests compile multiple generated Java sources in one batch and load each declared class.
- Unit tests report generated-source compiler diagnostics for an intentionally invalid source unit.
- Integration tests start an application with controllers in distinct packages that share a simple class name.
- Integration tests verify every registered controller route is callable after batch compilation.
- Integration tests verify endpoint metadata is sorted and has no duplicate entries after concurrent source generation.
- Integration tests verify a generated-source failure leaves no generated routes or endpoint metadata in the application registry.
- Integration tests run the generated-controller batch repeatedly in one JVM and verify identical route behavior and endpoint metadata.
- The full Maven reactor `clean verify` runs on JDK 27 with zero failures, errors, or skipped tests.

## Dependency Rules

- Remove `com.javax0.sourcebuddy:SourceBuddy` from the runtime dependency graph.
- Do not add a runtime compiler, persistent bytecode cache, external build daemon, or framework dependency.
- Use only `java.compiler` APIs provided by JDK 27 for generated-controller compilation.
